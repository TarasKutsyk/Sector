# Project

The one file that tells an agent what this project is for. Humans edit it only on major pivots; current focus and progress live in the workstream cards, never here. If the repo already has a brief that says the same things (a README section, a design doc), point at it from the agent rules instead of duplicating it.

## Goal

What the project is trying to become, in a few lines. What good looks like: the observable end state that means the project succeeded (for example "a to-do app I actually use daily on my phone"), so an agent can check its direction against it. What "done" means for the current milestone lives in the branch cards and plans, not here.
